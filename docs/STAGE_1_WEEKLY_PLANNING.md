# Этап 1. Недельная модель планирования

## Почему модель изменена

Исходное ТЗ допускает разные занятия и ограничения для каждой календарной
недели. Прежняя модель хранила одно значение `Stream.lessons_count` и применяла
его ко всему диапазону генерации. При увеличении диапазона CP-SAT создавал
переменные для каждой комбинации «группа × дисциплина × тип × слот», поэтому
число переменных росло одновременно с числом групп и недель.

Теперь единица расчета — `PlanningWeek`, а требуемое число занятий хранится в
`WeeklyLessonDemand`. Семестр или модуль (`AcademicPeriod`) автоматически
разбивается на календарные недели. Нагрузка одной недели может быть скопирована
из другой, создана из импортированных значений и затем отредактирована.

## Добавленные сущности

- `AcademicPeriod` — семестр, модуль или произвольный учебный период.
- `PlanningWeek` — конкретный диапазон дат внутри периода.
- `WeeklyLessonDemand` — количество занятий конкретного потока на конкретной
  неделе и его приоритет.
- `StudentGroup` — нормализованная карточка группы. Старые поля
  `StreamGroup.group_name/group_size` временно сохранены для совместимости.
- `GenerationTask.planning_week_id` — связь запуска с рассчитываемой неделей.
- `ScheduleEntry.planning_week_id/source_stream_id/is_locked` — основа для
  недельной истории, фиксаций и последующего дорасписания.

## API

- `POST /api/v1/planning/periods` — создать период и календарные недели.
- `GET /api/v1/planning/periods` — получить периоды вместе с неделями.
- `GET /api/v1/planning/periods/{id}/weeks` — недели периода.
- `GET|PUT /api/v1/planning/weeks/{id}/demands` — чтение или полная замена
  нагрузки недели.
- `POST /api/v1/planning/weeks/{id}/demands/clone` — копирование нагрузки из
  другой недели либо из текущих значений потоков.
- `POST /api/v1/scheduler/generate` с `planning_week_id` — генерация строго в
  датах выбранной недели и по ее нагрузке.

Если нагрузка выбранной недели не настроена, задача завершается понятной
ошибкой. Это предотвращает молчаливое создание одинакового расписания на все
недели.

## Совместимость

Миграция заполняет `StudentGroup` из существующих `StreamGroup`. Старые
запросы генерации без `planning_week_id` продолжают использовать
`Stream.lessons_count`. Новые импорты одновременно поддерживают старую связь и
нормализованную карточку группы.

## Следующий шаг масштабирования

Недельное ограничение убирает множитель числа недель, но внутри большой недели
текущий движок пока создает отдельную переменную потоковой лекции для каждой
группы. Следующий этап алгоритма должен:

1. строить одну переменную на учебное событие, а группы хранить как участников;
2. делить граф событий на независимые компоненты по общим группам и
   преподавателям;
3. решать компоненты параллельно Celery-задачами;
4. назначать аудитории общей фазой по каждому слоту, чтобы параллельные части не
   заняли одну аудиторию;
5. поддерживать warm start и локальный пересчет только затронутой компоненты.

Такое разбиение сохраняет корректность жестких конфликтов и масштабируется
лучше, чем запуск одного CP-SAT на весь университет.
