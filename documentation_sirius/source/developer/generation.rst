Генерация, версии и диагностика
===============================

Маршруты генерации расположены под ``/api/v1/scheduler``. Задание расчёта
создаётся в API и выполняется worker-процессом. Результат хранится как версия,
а не перезаписывает опубликованное расписание.

Жизненный цикл задачи
---------------------

* ``pending`` — задача создана и ожидает выполнения;
* ``success`` — расчёт завершён;
* ``failed`` — расчёт завершился ошибкой;
* ``canceled`` — задача отменена.

Публикационный статус версии: ``draft``, ``published`` и ``archived``.
Публикация новой версии автоматически архивирует прежнюю опубликованную версию
того же периода.

Надёжность
----------

* Для области расчёта создаётся ``generation_lock``; пересекающийся запуск
  получает HTTP 409.
* Отмена отзывает корневую, callback- и component-задачи Celery.
* Потеря worker переводит задачу в ``failed``, сохраняет проблему и освобождает блокировку.
* Одна задача ограничена 14 календарными днями для контроля потребления памяти.

Ручное редактирование
---------------------

Перед сохранением ``schedule_entry`` проверяются пересечения группы,
преподавателя и аудитории, правила доступности, активность аудитории и границы
периода. Занятие можно зафиксировать через ``is_locked``; зафиксированные записи
сохраняют слот при инкрементальном пересчёте.

Диагностика
-----------

``generation_issue`` хранит причины неразмещённых занятий, дефицита аудиторий
и ошибок компонентов solver. Используйте:

* ``GET /scheduler/tasks/{id}/diagnostics``;
* ``GET /scheduler/tasks/{id}/components``;
* ``GET /scheduler/schedule/quality``.
