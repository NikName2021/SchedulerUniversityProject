# Аудит проекта «Умное Расписание»

Дата проверки: 25 июля 2026 года.

## Итог

Активный код backend и frontend проверен статически, модульными и
интеграционными тестами, production-сборкой и smoke-тестами в реальном
браузере. Найденные дефекты корректности и большинство технических рисков
устранены.

Проект **не следует публиковать в недоверенной сети**, пока API не получит
аутентификацию, авторизацию по ролям и ограничение частоты запросов. Сейчас
описанные в интерфейсе роли не являются механизмом RBAC, а изменяющие данные
endpoint доступны без учётной записи.

## Исправленные дефекты

### Планирование и данные

- Разделены потоки одной дисциплины, если у них разные преподаватели.
- Конфликты проверяются для преподавателя, группы и аудитории; поток,
  разделяемый группами, не считается конфликтом с самим собой.
- Значение «без аудитории» больше не создаёт ложные конфликты.
- Синхронизированы JSON-ограничения преподавателей и нормализованные правила
  доступности.
- Исправлены расчёт окон в метриках качества и проверка порядка
  «лекция перед семинаром».
- Все компоненты используют семь пар; седьмая пара попадает в Excel.
- Исправлена обработка несоставленного расписания и нулевых идентификаторов.
- Ошибка подготовки фоновой задачи теперь переводит задачу в `failed` и
  освобождает блокировку.

### API, импорт и экспорт

- Добавлена строгая Pydantic-валидация дат, номеров пар, списков групп и
  ресурсных настроек solver.
- Размер файла ограничен 10 МиБ; чтение выполняется порциями.
- Имена загружаемых файлов очищаются, расширения проверяются, удаление
  ограничено каталогом загрузок.
- Для XLSX ограничены размер ZIP, коэффициент распаковки и число элементов;
  для табличных данных — количество строк и столбцов.
- Неуспешный импорт откатывает транзакцию и удаляет сохранённый файл.
- CSV/XLS/XLSX обрабатываются явно; обязательные столбцы проверяются.
- Значения, начинающиеся с формульных символов Excel, нейтрализуются.
- Внутренний текст исключений больше не передаётся клиенту.

### Безопасность и эксплуатация

- Добавлены `TrustedHostMiddleware` и HTTP-заголовки защиты.
- В Nginx добавлены CSP и остальные security headers; лимит тела запроса
  уменьшен до 12 МиБ.
- PostgreSQL и backend в Docker Compose привязаны к loopback-интерфейсу.
- Примеры окружения очищены от секретов и дополнены безопасными настройками.
- Удалён неиспользуемый legacy-контур JWT/Telegram вместе с его зависимостями
  и конфигурацией.
- Backend-контейнер уже запускается от непривилегированного пользователя.
- Readiness проверяет не только соединение, но и точную Alembic-ревизию базы.
- Python-зависимости обновлены до версий без известных уязвимостей.

### Frontend

- Убрана повторная глобальная загрузка данных.
- Ошибки HTTP теперь показываются пользователю; optimistic update редактора
  откатывается при ошибке API.
- Неделя, семь пар и преобразования времени вынесены в единый набор правил.
- Скачивания открываются с `noopener,noreferrer`.
- Иконки-кнопки и ячейки календаря получили доступные имена и клавиатурное
  управление.
- Жёсткая подпись «Администратор» заменена на честную подпись локального
  оператора.

## Добавленные тесты

Backend: 42 теста.

- parser и безопасные загрузки;
- импорт, откат и очистка файлов;
- Excel-экспорт и защита от формул;
- конфликты групп, преподавателей и аудиторий;
- нормализованные правила доступности;
- качество расписания;
- жизненный цикл и масштабируемая генерация;
- ограничения API, security headers и readiness миграций.

Frontend: 5 тестов.

- семь пар и интервалы времени;
- обратимость преобразований времени;
- отклонение некорректного времени;
- безопасное открытие скачиваемых файлов.

## Остаточные риски

1. **Высокий:** нет production-аутентификации и RBAC. До реализации API
   должен быть доступен только через закрытый аутентифицированный контур.
2. **Средний:** нет rate limiting для импорта и запуска ресурсоёмкой
   генерации.
3. `npm audit --omit=dev` показывает два high-severity package record для
   одного advisory React Router. Advisory относится только к нестабильным RSC
   API, которые проект не использует; исправленная ветка 8.3.0 пока не
   опубликована под npm-тегом `latest`.
4. Конфигурация распределённого контура проверена, а worker покрыт тестами,
   но отдельный длительный end-to-end прогон с реальными PostgreSQL, Redis и
   Celery не выполнялся. Перед production-релизом нужен нагрузочный прогон
   целевого набора учебных данных.

## Миграция локальной базы

Обнаруженная локальная SQLite-база соответствовала исходной схеме до Alembic.
Перед изменением создана резервная копия:

`/private/tmp/SchedulerProjectFull-scheduler-pre-migration-20260725.db`

База отмечена ревизией `20260716_0001`, обновлена до
`20260720_0006 (head)` и повторно проверена через API. Инструкция для других
старых локальных баз добавлена в README.
