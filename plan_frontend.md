# План реализации Frontend (на базе дизайн-кода)

## 1. Анализ дизайн-кода
* **Эстетика:** Academic Neo-Minimalism (Академический нео-минимализм — строгий интерфейс с фокусом на контент).
* **Стиль:** Чтобы интерфейс расписания не выглядел дешево или как «база данных», мы внедряем сложную топологию отступов, микро-тени и пастельное цветовое кодирование предметов. 
* **Ключевой якорь отличия:** Отсутствие стандартных боковых меню админки (Sidebars) и использование легких переключателей (Pills) на чистом фоне `#F4F5F8` со строгим шрифтом `Plus Jakarta Sans`.

## 2. Архитектурный стек FrontEnd'а
Учитывая сложность Drag-and-Drop и необходимость рендеринга больших таблиц (сотни пар), нам потребуется полноценное SPA (Single Page Application):
* **Сборщик бандла:** Vite (отличная скорость разработки и HMR). 
* **Библиотека:** React 18.
* **Стилизация:** Эксклюзивно **Vanilla CSS** + CSS-переменные (`--css-variables`) без Tailwind. Это дает максимальный контроль над пиксельным совершенством.
* **Роутинг:** `react-router-dom` (v6) для быстрого перехода между вкладками Импорт/Преподаватели/Расписание без перезагрузки браузера.

## 3. Компонентная структура (React Tree)
Создаем 4 основных экрана.

1. **`<ImportPage />` (Главная загрузки):**
   * `<DragDropZone />` — С нативной оберткой событий onDrag/onDrop. Граница подсвечивается синим при наведении холста с файлом.
   * `<UploadHistory />` — Вывод статусов обработки (ОК/Ошибка).

2. **`<TeachersLimitsPage />` (Блокировка часов):**
   * `<TeacherListSidebar />` — Боковая панель с фильтрацией (быстрый поиск по десяткам фамилий).
   * `<CalendarGrid />` — Матрица рабочих часов. В React стейте (Context) каждая ячейка привязана к массиву заблокированных слотов текущего выбранного преподавателя. Клик — перерисовка блокировки.

3. **`<DashboardPage />` (Генерация):**
   * `<StatsRow />` — Хуки, считающие общее количество импортов.
   * `<SatOrchestrator />` — Блок управления решателем OR-Tools. Красивый прогресс-бар, подпитываемый периодическими опросами бэкенда через Redis/FastAPI.

4. **`<ScheduleBoardPage />` (Конечный результат):**
   * `<TableFilters />` — Обертка для переключателей (По Группе / По Преподавателю).
   * `<MainGrid />` — Двумерный массив отрисовки расписания.
   * `<ClassCard />` — Унифицированный компонент пары (цвет бордера зависит от типа пары).
   * `<DndContext />` — Обертка логики Drag and Drop для перемещения карточек руками, чтобы корректировать алгоритм администратором.

## 4. Разработка Design System (Карта стилей)
Для соблюдения "Cohesive Restraint" (Целостной сдержанности) мы создаем централизованный файл `theme.css`:
* **Типографика:** `Plus Jakarta Sans` (для заголовков) и моноширинный шрифт для счетчиков пар/часов.
* **Анимации (Motion Philosophy):** 
  - Разрешено только ускоренное появление (fade-in) модальных окон на 150ms.
  - Легкое сжатие главных кнопок (`transform: scale(0.98)`) для ощущения физики нажатия.
  - Никакой избыточной декоративной анимации (запрещено).
